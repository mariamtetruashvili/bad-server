## 🛡️ Аудит безопасности и исправленные уязвимости

В ходе работы над проектом были выявлены и устранены следующие уязвимости:

### 1. NoSQL-инъекции
* **Проблема:** Пользовательские объекты (например, `{$gt: ""}`) могли попадать напрямую в запросы к базе данных.
* **Решение:** Внедрена библиотека `express-mongo-sanitize`. В контроллерах добавлена строгая проверка типов данных (например, `typeof status !== 'string'`) для предотвращения инъекций через параметры запроса.

### 2. XSS (Межсайтовый скриптинг)
* **Проблема:** В полях комментариев к заказу была возможна вставка вредоносного JavaScript-кода.
* **Решение:** Интегрированы библиотеки `sanitize-html` и `xss` для фильтрации ввода. Установлен пакет `helmet` для настройки безопасных HTTP-заголовков и защиты от инъекций скриптов.

### 3. Path Traversal (Обход директорий)
* **Проблема:** При загрузке файлов использовалось оригинальное имя, что позволяло манипулировать путями файловой системы.
* **Решение:** Реализована генерация уникальных безопасных имен файлов (timestamp + random). Оригинальное имя файла теперь сохраняется только как метаданное, а доступ к файлам вне разрешенных директорий ограничен.

### 4. DDoS и Rate Limiting
* **Проблема:** Сервер был уязвим для перегрузки большим количеством автоматизированных запросов.
* **Решение:** Установлен `express-rate-limit`. Настроено ограничение: не более 50 запросов в течение 15 минут с одного IP-адреса.

### 5. ReDoS (Отказ в обслуживании через регулярные выражения)
* **Проблема:** Неоптимизированные регулярные выражения могли вызвать зависание сервера при обработке специально сформированных строк.
* **Решение:** Все регулярные выражения (включая валидацию телефона) заменены на безопасные аналоги. Добавлены ограничения на максимальную длину строк в схемах валидации Joi/Celebrate.

### 6. Переполнение буфера
* **Проблема:** Отсутствие лимитов на размер входящих данных и файлов.
* **Решение:** Лимит `express.json` ограничен до `10kb`. Для загрузки файлов установлены границы: минимум 2kb, максимум 10mb, чтобы избежать переполнения памяти и диска.

## Подготовка к работе
1. Склонировать репозиторий
2. Запустить docker
```bash
docker compose up -d
```
3. Наполнить базу данных
[README.md](.dump%2FREADME.md)
4. Перейти по адресу http://localhost:5173/ и на странице должны быть продукты.
5. На странице http://localhost/login/ можно авторизоваться.
6. Админка находится по адресу http://localhost/admin/
